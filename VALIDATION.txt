with normal core and fixed 12000 cycles. Evidence consists of native VGA
captures and bounded read-only guest-state samples. All sessions used disposable
game copies. Test memory dumps, altered test worlds, and host instrumentation
are not included in either the playable release or the shareable patch.

COMPANION BUG REPRODUCTIONS AND REPAIR

1. Stale automatic policy, reproduced in delivered v7.
   Hold during combat captured native schedule 0. Ending combat with C put
   the Avatar on follow 31 but skipped the held companion on wait 15. Auto
   then restored stale combat 0. Shamino pursued again; the selected spider's
   HP fell from 9 to 6. The inverse transition also needed synchronization.

   The new callbacks run after actual native begin/end transitions and keep
   stored ordinary combat/follow policy current. Actual combat end changes
   explicit Attack to Hold and clears its target, while preserving existing
   Hold and owned Move. Current behavior tests repeated both C transitions:
   Auto restored combat 0 after start and follow 31 after end.

2. Native Avatar movement overrides manual companions, reproduced before
   the new movement hook.
   With every actor held, normal right-mouse Avatar movement reset the party
   to follow inside resident 4:07AB. Held Tseramed took a one-tile step even
   though his tactical record still said Hold.

   The repair protects manually controlled non-Avatar companions at that
   reset itself. On the current behavior candidate, the Avatar moved from
   (1662,1767) to (1672,1767); all seven held companions stayed at the same
   positions. Spark's separate Move kept route 52328, advanced through
   (1660,1765), (1668,1772), and (1672,1776), then completed in Hold. The other
   six held companions stayed fixed. Returning Spark to Auto restored native
   following while those six remained fixed.

   Spark's live ranged target 304 and combat schedule 0 also survived ordinary
   Avatar movement. After the target was removed from the native NPC table,
   his order became Hold without selecting another foe.

LIMITS AND RETAINED NATIVE BEHAVIOR

The exact reported offscreen regrouping and apparent teleport were not
reproduced. Two real command-ownership bugs were reproduced and repaired.
The original automatic-follow catch-up path was traced separately: resident
41:21BF admits follow schedule 31 and can call 249:0039 plus coordinate setter
86:1648 after an offscreen check. No actual teleport was measured in these
reproductions, and ordinary automatic catch-up remains part of the engine.

Native C start/end tests used the keyboard owner. The other guarded script
and dialog callers were statically audited, not separately triggered live.
C retains its original dependence on the Avatar's schedule. If the Avatar is
explicitly on Hold, return the Avatar to Auto before using C to end ordinary
combat. This release observes actual native transitions rather than defining
a new global combat-state model.

Orders remain session state and are cleared on loading; the save format stays
native. This is targeted scenario validation, not a complete campaign,
equipment, quest, or emulator-configuration certification. Installer tests
ran on the Linux host; Windows and macOS command examples were not separately
executed on those operating systems.
